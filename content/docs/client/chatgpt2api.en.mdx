ChatGPT2API Go wraps ChatGPT Web capabilities in a self-hosted API service. It provides OpenAI- and Anthropic-compatible endpoints, account pooling, image management, audit logs, and a web console.

[GitHub repository](https://github.com/yukkcat/gpt2api-go) · [v1.4.2 Release](https://github.com/yukkcat/gpt2api-go/releases/tag/v1.4.2) · [Changelog](https://github.com/yukkcat/gpt2api-go/blob/main/CHANGELOG.md) · [README](https://github.com/yukkcat/gpt2api-go/blob/main/README.md)

> **Risk notice:** This project accesses ChatGPT Web for technical research and is not an official OpenAI API. Upstream interfaces and risk controls can change and may restrict or ban accounts. Do not use important, frequently used, or high-value accounts. Follow the applicable terms and laws.

## Current implementation

This page has been synchronized with the `yukkcat/gpt2api-go` `v1.4.2` source. The backend is written in Go, the console uses Next.js, and the compiled frontend is served directly by the Go service.

| Area | Current implementation |
| --- | --- |
| Compatible APIs | Chat Completions, Responses, Anthropic Messages, image generation, and image editing |
| Multimodal input | OpenAI-style image input, reference-image upload, and lightweight text/PDF extraction |
| Account pool | Multi-account selection, quota and state tracking, AT/RT handling, image concurrency, failures, and rate limits |
| Tool calls | OpenAI `tool_calls`, Anthropic `tool_use`, and Responses `function_call` |
| Image workflows | Synchronous responses, SSE streaming, and PostgreSQL-backed durable async jobs |
| Administration | Web console, image management, call logs, request tracing, and runtime metrics |

## Quick deployment

### Docker

```bash
git clone https://github.com/yukkcat/gpt2api-go.git
cd gpt2api-go

# Edit config.json and replace auth-key with your own strong secret
docker compose up -d --build
```

Default addresses:

| Purpose | Address |
| --- | --- |
| Admin console | `http://localhost:3000` |
| API Base URL | `http://localhost:3000/v1` |

You can also build and run a single container:

```bash
docker build -t chatgpt2api-go .
docker run --rm \
  -p 3000:80 \
  -v "$PWD/data:/app/data" \
  -e CHATGPT2API_AUTH_KEY=<set-a-strong-secret> \
  chatgpt2api-go
```

## API endpoints

All AI endpoints use a Bearer key:

```http
Authorization: Bearer <auth-key>
```

| Endpoint | Method | Description |
| --- | --- | --- |
| `/v1/models` | `GET` | Lists the currently available models |
| `/v1/chat/completions` | `POST` | OpenAI Chat Completions-compatible endpoint |
| `/v1/responses` | `POST` | OpenAI Responses-compatible endpoint |
| `/v1/messages` | `POST` | Anthropic Messages-compatible endpoint |
| `/v1/images/generations` | `POST` | Image generation; also submits or queries async jobs |
| `/v1/images/edits` | `POST` | Image editing with multiple references and async support |
| `/v1/images/tasks/{task_id}` | `GET` | Polls and claims an async image job owned by the current key |
| `/v1/images/tasks/{task_id}/results/{position}` | `GET` | Downloads a claimed async image result |

### Text example

```bash
curl http://localhost:3000/v1/chat/completions \
  -H "Authorization: Bearer <auth-key>" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "gpt-5",
    "messages": [{"role":"user","content":"Introduce this project"}],
    "stream": true
  }'
```

### Synchronous image example

```bash
curl http://localhost:3000/v1/images/generations \
  -H "Authorization: Bearer <auth-key>" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "gpt-image-2",
    "prompt": "A cat floating in space, cinematic lighting",
    "n": 1
  }'
```

## Asynchronous image jobs

Async execution is implemented in the source. It is not a separate model and it is not `stream: true`. Add `async: true` to the normal image request; the service returns a task ID immediately and a background worker continues the job.

```text
submit async=true -> receive HTTP 202 and task ID -> background generation -> poll -> claim result
```

### Server requirements

Async jobs are disabled by default. The server must meet all of these requirements:

1. Use PostgreSQL account storage with `STORAGE_BACKEND=postgres`.
2. Configure `DATABASE_URL` and `CHATGPT2API_ACCOUNT_ENCRYPTION_KEY`.
3. Set `CHATGPT2API_ASYNC_IMAGES_ENABLED=true`.
4. Add permitted User Key `subject_id` values to `CHATGPT2API_ASYNC_IMAGE_ALLOWED_SUBJECTS`; the administrator root key uses `admin`.
5. In a multi-instance deployment, mount the same `CHATGPT2API_ASYNC_IMAGE_ASSET_ROOT` for every worker.

### Submit a job

```bash
curl http://localhost:3000/v1/images/generations \
  -H "Authorization: Bearer <auth-key>" \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: stable-request-id" \
  -d '{
    "model": "gpt-image-2",
    "prompt": "A cat floating in space",
    "async": true
  }'
```

The service responds with HTTP `202`. Its body, `Location`, and `Retry-After` values tell the client how to poll:

```json
{
  "id": "img_...",
  "object": "image.task",
  "status": "queued",
  "mode": "generation",
  "model": "gpt-image-2",
  "created_at": 1787190000,
  "expires_at": 1787193600,
  "poll_url": "/v1/images/tasks/img_...?model=gpt-image-2",
  "retry_after_seconds": 4
}
```

`Idempotency-Key` prevents a network retry from creating the same job twice. The body may instead contain `idempotency_key`; if the header and body field are both present, their values must match.

### Poll and claim the result

```bash
curl "http://localhost:3000/v1/images/tasks/<task_id>?model=gpt-image-2" \
  -H "Authorization: Bearer <auth-key>"
```

Polling must use **the same API key and the same `model` used for submission**.

| Status | Meaning |
| --- | --- |
| `queued` | Accepted and waiting for a worker |
| `running` | A worker is calling the upstream |
| `succeeded` | Generation completed and the result can be claimed |
| `failed` | The job failed and returns an OpenAI-style error |

The first successful claim returns HTTP `200` with `data[]`:

```json
{
  "id": "img_...",
  "object": "image.task",
  "status": "succeeded",
  "model": "gpt-image-2",
  "data": [{"url":"/v1/images/tasks/img_.../results/0?model=gpt-image-2","revised_prompt":"..."}],
  "usage": {"total_tokens": 123}
}
```

Omitting `response_format` or passing `url` returns download URLs. Passing `b64_json` explicitly returns inline Base64.

> **Only the successful `data[]` claim is limited to one; the image itself is not limited to one download.** Polling the same task again returns `404` to prevent duplicate downstream settlement. A URL can be downloaded repeatedly with the same Bearer key until the job expires.

```bash
curl -L \
  -H "Authorization: Bearer <auth-key>" \
  "http://localhost:3000/v1/images/tasks/<task_id>/results/0?model=gpt-image-2" \
  -o image.png
```

For gateways that cannot forward GET requests, the original image endpoint also supports compatibility polling. A pending POST poll returns HTTP `202`; a successful poll returns HTTP `200`:

```bash
curl http://localhost:3000/v1/images/generations \
  -H "Authorization: Bearer <auth-key>" \
  -H "Content-Type: application/json" \
  -d '{"model":"gpt-image-2","task_id":"img_..."}'
```

Image editing supports async execution as well: add `-F "async=true"` to a multipart `/v1/images/edits` request. `async: true` and `stream: true` cannot be enabled together.

## Async job configuration

| Environment variable | Default | Purpose |
| --- | --- | --- |
| `CHATGPT2API_ASYNC_IMAGES_ENABLED` | `false` | Enables async image jobs; PostgreSQL only |
| `CHATGPT2API_ASYNC_IMAGE_ALLOWED_SUBJECTS` | Empty | Allowed `subject_id` list; empty rejects all submissions |
| `CHATGPT2API_ASYNC_IMAGE_WORKERS` | `8` | Background worker count, from 1 to 64 |
| `CHATGPT2API_ASYNC_IMAGE_QUEUE_CAPACITY` | `64` | Global outstanding-job limit |
| `CHATGPT2API_ASYNC_IMAGE_OWNER_OUTSTANDING` | `8` | Outstanding-job limit per User Key |
| `CHATGPT2API_ASYNC_IMAGE_OWNER_SUBMISSIONS_PER_MINUTE` | `30` | Submission limit per User Key per minute |
| `CHATGPT2API_ASYNC_IMAGE_RESULT_TTL_MINUTES` | `60` | Retention for unclaimed results, up to 7 days |
| `CHATGPT2API_ASYNC_IMAGE_MAX_STORED_BYTES` | `10 GiB` | Global storage limit for unclaimed results |
| `CHATGPT2API_ASYNC_IMAGE_ASSET_ROOT` | `data/image-jobs` | Input and result asset directory |

## Local development

Use the Go version declared by the repository's `go.mod`:

```bash
go test ./...
make run
```

To rebuild the web console before running:

```bash
make web
make run
```
