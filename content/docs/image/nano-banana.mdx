`nano-banana2` 和 `nano-banana-pro` 使用与 [GPT Image 系列](/docs/image/gpt-image-2)相同的 OpenAI Images 请求与响应结构。保留完整模型名，具体可用尺寸、数量及扩展参数以当前模型和渠道为准。

本页的 Nano 模型使用 OpenAI Images 调用。需要 `contents`、`generationConfig` 请求时，使用 [Gemini 协议](/docs/image/gemini)页面列出的 Gemini 图片模型；不要把 Nano 名称直接替换到 Gemini 路径中。模型可用性以密钥所属分组为准。

## 接口与认证

| 项目 | 值 |
| --- | --- |
| API 根地址 | `https://api.klong.lat` |
| OpenAI SDK Base URL | `https://api.klong.lat/v1` |
| 认证 | `Authorization: Bearer <API_KEY>` |
| 文生图 | `POST /v1/images/generations` |
| 图片编辑 | `POST /v1/images/edits` |
| 模型 | `nano-banana2`、`nano-banana-pro` |

## 文生图

首次接入建议明确像素尺寸、返回方式和文件编码，并使用 `n: 1`。使用 Pro 时将 `model` 改为 `nano-banana-pro`。

<Tabs items={['cURL', 'Python']}>
<Tab>

```bash
curl https://api.klong.lat/v1/images/generations \
  -H "Authorization: Bearer <API_KEY>" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "nano-banana2",
    "prompt": "木桌上的红苹果，柔和棚拍光线，极简背景",
    "size": "1024x1024",
    "n": 1,
    "response_format": "url",
    "output_format": "webp"
  }'
```

</Tab>
<Tab>

安装 `openai` 后运行：

```python
from openai import OpenAI

client = OpenAI(
    api_key="<API_KEY>",
    base_url="https://api.klong.lat/v1",
)
result = client.images.generate(
    model="nano-banana2",
    prompt="木桌上的红苹果，柔和棚拍光线，极简背景",
    response_format="url",
    size="1024x1024",
    n=1,
    extra_body={
        "output_format": "webp",
    },
)
print(result.data[0].url)
```

`extra_body` 用于 SDK 尚未暴露为命名参数的服务扩展字段。

</Tab>
</Tabs>

## 图片编辑

编辑请求提供提示词和参考图。JSON 支持 URL 或 Data URL；multipart 支持上传本地文件。尺寸与返回参数的写法和文生图一致。

<Tabs items={['JSON', 'multipart']}>
<Tab>

```bash
curl https://api.klong.lat/v1/images/edits \
  -H "Authorization: Bearer <API_KEY>" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "nano-banana-pro",
    "prompt": "改成日系水彩风，保留主体和构图",
    "image": ["https://example.com/input.png"],
    "size": "1024x1024",
    "n": 1,
    "response_format": "url",
    "output_format": "png"
  }'
```

将示例 URL 替换为服务端可访问的图片地址，也可以使用 `data:image/png;base64,<PNG_BASE64>`。参考图字段支持 `image`、`images`、`image_url`、`reference_images`，单张传字符串，多张传数组。

</Tab>
<Tab>

```bash
curl https://api.klong.lat/v1/images/edits \
  -H "Authorization: Bearer <API_KEY>" \
  -F "model=nano-banana2" \
  -F "prompt=改成日系水彩风，保留主体和构图" \
  -F "image=@input.png" \
  -F "size=1024x1024" \
  -F "n=1" \
  -F "response_format=b64_json" \
  -F "output_format=png"
```

多个文件可重复使用 `image[]`。让 cURL 自动设置包含 boundary 的 `Content-Type`。

</Tab>
</Tabs>

## 尺寸、交付方式与编码

| 参数 | 控制内容 | 示例 |
| --- | --- | --- |
| `size` | 目标像素 | `"2048x2048"` |
| `aspect_ratio` | 图片比例 | `"16:9"` |
| `image_size` | 分辨率档位 | `"1K"`、`"2K"`、`"4K"` |
| `response_format` | URL 或 Base64 交付 | `"url"`、`"b64_json"` |
| `output_format` | 图片文件的真实编码 | `"png"`、`"jpeg"`、`"webp"` |

明确像素 `size` 优先于同时传入的比例和档位。也可以省略 `size`，改传 `aspect_ratio: "16:9"` 与 `image_size: "2K"`；2026-09-24 的 Nano2 实测输出为 `2752x1536`，不是固定的 `2048x1152`。单独传比例或档位属于平台接受的写法，但仍受上游能力限制；本轮未穷举这些组合或 4K。目标像素是否精确满足取决于渠道的尺寸处理模式，不能仅凭请求中的 `size` 判断实际输出。

`output_format: "webp"` 可以与 URL 或 Base64 搭配，和交付方式无关。省略时保留处理后的图片编码；JPEG 转码会将透明区域铺白底。详细优先级、兼容别名和尺寸限制见[OpenAI 图片参数](/docs/image/openai-parameters)。

## 读取返回图片

非流式响应的图片位于 `data` 数组。返回方式优先级为 **分组强制策略 > 请求 `response_format` > 分组默认策略**。分组可选择默认 URL、默认 Base64、强制 URL、强制 Base64；显式参数只在未被强制策略覆盖时生效。以下示例均以未强制覆盖为前提。

<Tabs items={['URL', 'Base64']}>
<Tab>

请求 `response_format: "url"` 时：

```json
{
  "created": 1787600000,
  "data": [{"url": "https://example.com/images/result.webp"}]
}
```

读取 `data[].url`，需要长期使用的图片请及时保存到自己的存储。

</Tab>
<Tab>

请求 `response_format: "b64_json"` 和 `output_format: "webp"` 时：

```json
{
  "created": 1787600000,
  "data": [{"b64_json": "<WEBP_BASE64>"}]
}
```

`b64_json` 不带 Data URL 前缀。沿用上面的 Python SDK，将 `response_format` 改为 `b64_json` 后保存：

```python
import base64
from pathlib import Path

for index, item in enumerate(result.data):
    Path(f"result-{index}.webp").write_bytes(base64.b64decode(item.b64_json))
```

</Tab>
</Tabs>

以上响应省略了用量等字段。Images 返回结构与 Chat 的 Markdown 图片、Gemini 的 `candidates[].content.parts[]` 不同。渠道支持 Images 流式时，`stream: true` 的完成事件按最终交付策略使用 `url` 或 `b64_json`；URL 事件是平台扩展，格式见 [GPT Image 系列](/docs/image/gpt-image-2)。这不表示本轮已验证每个 Nano 模型的 Images SSE。

## 已验证范围与限制

2026-09-24 实测通过 Nano2/Pro 文生图和图生图、URL/Base64，以及部分 PNG/JPEG/WebP 组合。Nano2 还验证了标准 Chat 图生图和 Chat SSE，后者首次返回 400、重试后成功；这不是每种模型与协议组合均无错误的保证。

- 建议使用 `n: 1`；输入参考图数量与输出图片数量是两个概念，多图支持应按渠道验证。
- 当前接口不支持 `mask`、`output_compression`；`background` 不提供透明背景控制。
- NewAPI 的 Chat 入口不接受 `response_format: "url"` 或 `"b64_json"` 这种字符串图片参数。使用分组默认交付方式，或改用本页 Images 接口按请求控制返回方式。
- 本轮没有完成 Nano Responses 的端到端验证，不能仅替换 GPT Responses 示例中的模型名就视为已支持。Chat 已验证的请求与返回见[对话与 Responses 生图](/docs/image/openai-chat-responses)。
