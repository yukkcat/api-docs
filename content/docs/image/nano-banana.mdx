Nano Banana 支持两套请求格式：OpenAI 兼容的 Images API，以及 Gemini 原生的 `generateContent`。两套格式都可以用于文生图；需要编辑已有图片时，OpenAI 格式使用 `/v1/images/edits`，Gemini 格式在 `contents.parts` 中附带图片。

## 模型

| 模型 | 说明 |
| --- | --- |
| `nano-banan2` | Nano Banana 2 模型，支持 OpenAI Images API 和 Gemini 原生格式。 |
| `nano-banana-pro` | Nano Banana Pro 模型，支持 OpenAI Images API 和 Gemini 原生格式。 |
| `gemini-3.1-flash-image-preview` | 兼容模型，按本页 Gemini 原生格式调用；可用能力以服务端配置为准。 |
| `gemini-3-pro-image-preview` | 兼容模型，按本页 Gemini 原生格式调用；可用能力以服务端配置为准。 |

请求体里的 `model` 和原生 Gemini URL 中的模型名使用同一个模型 ID。所有列出的 Gemini 模型使用同一套原生参数。

## 选择请求格式

| 需求 | 使用方式 |
| --- | --- |
| 已经接入 OpenAI SDK 或 Images API | `POST /v1/images/generations` |
| 编辑图片，使用 OpenAI 兼容参数 | `POST /v1/images/edits` |
| 需要 Gemini 原生字段 | `POST /v1beta/models/{model}:generateContent` |
| 需要 Gemini 原生流式响应 | 将方法名改为 `:streamGenerateContent`，请求体保持一致 |

## OpenAI 兼容格式

### 文生图

```http
POST https://api.klong.lat/v1/images/generations
Authorization: Bearer <API_KEY>
Content-Type: application/json
```

```json
{
  "model": "nano-banan2",
  "prompt": "木桌上的红苹果，柔和棚拍光线，极简背景",
  "size": "1024x1024",
  "response_format": "url"
}
```

`nano-banana-pro` 的调用方式相同，只需要把 `model` 改成 `nano-banana-pro`。不传 `response_format` 时，服务端默认返回 URL；需要 Base64 时显式传 `b64_json`。`size` 使用服务端支持的尺寸值。

### 图生图

```http
POST https://api.klong.lat/v1/images/edits
Authorization: Bearer <API_KEY>
Content-Type: multipart/form-data
```

```bash
curl -X POST "https://api.klong.lat/v1/images/edits" \
  -H "Authorization: Bearer <API_KEY>" \
  -F "model=nano-banan2" \
  -F "prompt=改成日系水彩风，保留主体和构图" \
  -F "response_format=url" \
  -F "image=@input.png"
```

输入图片也可以使用 `image_url` 或 `image_b64`，具体字段以服务端接口为准。

## Gemini 原生格式

### 请求地址与请求头

```http
POST https://api.klong.lat/v1beta/models/{model}:generateContent
x-goog-api-key: <API_KEY>
Content-Type: application/json
```

把 `{model}` 替换为 `nano-banan2` 或 `nano-banana-pro`。比例与分辨率统一放在 `generationConfig.imageConfig` 中。

如果当前服务配置允许，也可以用 `Authorization: Bearer <API_KEY>` 认证；同一个请求只保留一种认证头，具体以服务端配置为准。

### 原生文生图请求

```json
{
  "contents": [
    {
      "role": "user",
      "parts": [
        { "text": "木桌上的红苹果，柔和棚拍光线，极简背景" }
      ]
    }
  ],
  "generationConfig": {
    "responseModalities": ["IMAGE"],
    "imageConfig": {
      "aspectRatio": "1:1",
      "imageSize": "1K"
    }
  }
}
```

OpenAI 的 `size` 和 `response_format` 不属于 Gemini 原生请求。Gemini 图像参数如下：

有些参考文档会使用 `generationConfig.responseFormat.image`，那是另一种服务版本的写法。本服务当前按原生 `generationConfig.imageConfig` 处理；不要把两套字段同时放进同一个请求，实际部署行为以服务端为准。

| 字段 | 说明 |
| --- | --- |
| `responseModalities` | 返回图片时传 `['IMAGE']`。 |
| `imageConfig.aspectRatio` | 图片比例，例如 `1:1`、`16:9`、`3:4`。不需要固定比例时省略。 |
| `imageConfig.imageSize` | 分辨率档位，例如 `1K`、`2K`、`4K`；以当前模型和服务端支持范围为准。 |

### 返回模式

`responseModalities` 决定响应中希望得到的内容类型：

| 值 | 常见结果 | 说明 |
| --- | --- | --- |
| `['IMAGE']` | `inlineData`（Base64） | 当前文档推荐的图片返回方式。 |
| `['TEXT']` | `fileData.fileUri` 或文本 | 只有服务端启用 URL/文本转换时才可用，不能假设所有部署都支持。 |
| `['IMAGE', 'TEXT']` | 图片和 URL/文本同时返回 | 同样取决于服务端是否启用混合返回。 |

原生图片响应优先读取 `candidates[].content.parts[]`，不要只按数组下标读取：响应中可能先出现文字说明，再出现图片。常用字段如下：

| 响应字段 | 用途 |
| --- | --- |
| `inlineData.mimeType` + `inlineData.data` | 拼接 `data:{mimeType};base64,{data}`，直接显示或保存。 |
| `fileData.fileUri` | 读取服务端返回的图片 URL（如果当前部署支持 URL 返回）。 |
| `text` | 模型返回的文字说明，不一定包含图片。 |

> 当前服务未明确开启 `TEXT` 或混合返回时，请固定使用 `['IMAGE']`，并以 `inlineData` 是否存在判断是否成功。原生请求只写 `imageConfig`；不要添加 OpenAI 的 `response_format` 或 `responseFormat` 字段。

### 比例与分辨率速查

下面是 Gemini 图像模型常见的目标像素，实际结果仍以当前模型和服务端返回的图片尺寸为准：

| 比例 | 1K | 2K | 4K |
| --- | --- | --- | --- |
| `1:1` | 1024×1024 | 2048×2048 | 4096×4096 |
| `16:9` | 1376×768 | 2752×1536 | 5504×3072 |
| `9:16` | 768×1376 | 1536×2752 | 3072×5504 |
| `4:3` | 1200×896 | 2400×1792 | 4800×3584 |
| `3:4` | 896×1200 | 1792×2400 | 3584×4800 |
| `3:2` | 1264×848 | 2528×1696 | 5056×3392 |
| `2:3` | 848×1264 | 1696×2528 | 3392×5056 |
| `5:4` | 1152×928 | 2304×1856 | 4608×3712 |
| `4:5` | 928×1152 | 1856×2304 | 3712×4608 |
| `21:9` | 1584×672 | 3168×1344 | 6336×2688 |

`imageSize` 必须使用大写的 `1K`、`2K` 或 `4K`。`aspectRatio` 和 `imageSize` 都省略时，由上游自行决定；文生图建议显式填写两者。不要传 `aspectRatio: "auto"`，需要自动比例时直接省略字段。

部分上游还提供 `8:1`、`4:1`、`1:4`、`1:8` 这类超宽比例。它们并非所有模型或部署都开放；只有在服务端明确支持并且实际返回成功时才使用，遇到 `400` 时请改用上面的通用比例。

参考实现常见的 1K 尺寸如下；如果服务端按同一比例放大，2K、4K 通常约为下表的 2 倍、4 倍，但最终像素仍以实际响应为准：

| 比例 | 参考 1K 尺寸 |
| --- | --- |
| `8:1` | 2928×352 |
| `4:1` | 2064×512 |
| `1:4` | 512×2064 |
| `1:8` | 352×2928 |

### 原生响应

图片通常位于 `candidates[0].content.parts` 的 `inlineData` 节点：

```json
{
  "candidates": [
    {
      "content": {
        "parts": [
          {
            "inlineData": {
              "mimeType": "image/png",
              "data": "<BASE64>"
            }
          }
        ]
      }
    }
  ]
}
```

## Gemini 原生图生图

### Base64 输入

在 `parts` 中同时传文字和 `inlineData`。输入图片使用原生 Gemini 的 camelCase 字段：

```json
{
  "contents": [{
    "role": "user",
    "parts": [
      { "text": "改成日系水彩风，保留主体和构图" },
      {
        "inlineData": {
          "mimeType": "image/png",
          "data": "<BASE64>"
        }
      }
    ]
  }],
  "generationConfig": {
    "responseModalities": ["IMAGE"],
    "imageConfig": { "imageSize": "2K" }
  }
}
```

### URL 输入

如果服务端支持远程图片输入，可以使用 `fileData`：

```json
{
  "contents": [{
    "role": "user",
    "parts": [
      { "text": "改成日系水彩风，保留主体和构图" },
      {
        "fileData": {
          "mimeType": "image/png",
          "fileUri": "https://example.com/input.png"
        }
      }
    ]
  }],
  "generationConfig": {
    "responseModalities": ["IMAGE"],
    "imageConfig": { "imageSize": "2K" }
  }
}
```

`inlineData` 和 `fileData` 都是图片 part，可以按 `contents[].parts[]` 中的顺序混合传入；远程 URL 必须能被服务端访问。参考资料常见的“最多 14 张”不是本接口的固定承诺，图片数量上限以当前模型、服务端配置和实际错误响应为准。

省略 `imageConfig.aspectRatio` 时，服务端可以根据参考图决定比例；需要固定比例时再传 `aspectRatio`。

## 常见问题

### OpenAI 和 Gemini 请求能混用吗？

不能直接混用字段。OpenAI 兼容入口使用 `model`、`prompt`、`size` 和 `response_format`；Gemini 原生入口使用 `contents`、`generationConfig.responseModalities` 和 `generationConfig.imageConfig`。模型可以相同，但请求体要按入口书写。

### `nano-banan2` 和 `nano-banana-pro` 怎么选？

先使用 `nano-banan2` 验证请求格式和业务流程；需要使用 Pro 模型时把模型名替换为 `nano-banana-pro`，其他字段保持不变。具体速度、额度和可用尺寸以服务端当前配置为准。

### 为什么看不到图片？

先检查响应是否包含 `candidates[].content.parts[].inlineData.data`，并根据 `mimeType` 拼接 `data:{mimeType};base64,{data}`。如果使用 OpenAI 兼容格式，则读取 `data[0].url` 或 `data[0].b64_json`。

长段中文仍可能出现错字、漏字或顺序错误。图片适合做构图和视觉草稿；需要准确排版的标题、条款或正文，建议生成后在设计软件中添加。
