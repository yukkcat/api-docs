Nano Banana 支持两套请求格式：OpenAI 兼容的 Images API，以及 Gemini 原生的 `generateContent`。两套格式都可以用于文生图；需要编辑已有图片时，OpenAI 格式使用 `/v1/images/edits`，Gemini 格式在 `contents.parts` 中附带图片。

## 模型

| 模型 | 说明 |
| --- | --- |
| `nano-banana-2` | Nano Banana 新版模型，支持 OpenAI Images API 和 Gemini 原生格式。 |
| `nano-banana-pro` | Nano Banana Pro 模型，支持 OpenAI Images API 和 Gemini 原生格式。 |
| `gemini-3.1-flash-image-preview` | 兼容模型，按本页 Gemini 原生格式调用；可用能力以服务端配置为准。 |
| `gemini-3-pro-image-preview` | 兼容模型，按本页 Gemini 原生格式调用；可用能力以服务端配置为准。 |

请求体里的 `model` 和原生 Gemini URL 中的模型名使用同一个模型 ID。所有列出的 Gemini 模型使用同一套原生参数。

## 选择请求格式

| 需求 | 使用方式 |
| --- | --- |
| 已经接入 OpenAI SDK 或 Images API | `POST /v1/images/generations` |
| 编辑图片，使用 OpenAI 兼容参数 | `POST /v1/images/edits` |
| 需要 Gemini 原生字段 | `POST /v1beta/models/{model}:generateContent` |
| 需要 Gemini 原生流式响应 | 将方法名改为 `:streamGenerateContent`，请求体保持一致 |

## OpenAI 兼容格式

### 文生图

```http
POST https://api.klong.lat/v1/images/generations
Authorization: Bearer <API_KEY>
Content-Type: application/json
```

```json
{
  "model": "nano-banana-2",
  "prompt": "木桌上的红苹果，柔和棚拍光线，极简背景",
  "size": "1024x1024",
  "response_format": "url"
}
```

`nano-banana-pro` 的调用方式相同，只需要把 `model` 改成 `nano-banana-pro`。不传 `response_format` 时，服务端默认返回 URL；需要 Base64 时显式传 `b64_json`。`size` 使用服务端支持的尺寸值。

### 图生图

```http
POST https://api.klong.lat/v1/images/edits
Authorization: Bearer <API_KEY>
Content-Type: multipart/form-data
```

```bash
curl -X POST "https://api.klong.lat/v1/images/edits" \
  -H "Authorization: Bearer <API_KEY>" \
  -F "model=nano-banana-2" \
  -F "prompt=改成日系水彩风，保留主体和构图" \
  -F "response_format=url" \
  -F "image=@input.png"
```

输入图片也可以使用 `image_url` 或 `image_b64`，具体字段以服务端接口为准。

## Gemini 原生格式

### 请求地址与请求头

```http
POST https://api.klong.lat/v1beta/models/{model}:generateContent
x-goog-api-key: <API_KEY>
Content-Type: application/json
```

把 `{model}` 替换为 `nano-banana-2` 或 `nano-banana-pro`。比例与分辨率统一放在 `generationConfig.imageConfig` 中。

### 原生文生图请求

```json
{
  "contents": [
    {
      "role": "user",
      "parts": [
        { "text": "木桌上的红苹果，柔和棚拍光线，极简背景" }
      ]
    }
  ],
  "generationConfig": {
    "responseModalities": ["IMAGE"],
    "imageConfig": {
      "aspectRatio": "1:1",
      "imageSize": "1K"
    }
  }
}
```

OpenAI 的 `size` 和 `response_format` 不属于 Gemini 原生请求。Gemini 图像参数如下：

| 字段 | 说明 |
| --- | --- |
| `responseModalities` | 返回图片时传 `['IMAGE']`。 |
| `imageConfig.aspectRatio` | 图片比例，例如 `1:1`、`16:9`、`3:4`。不需要固定比例时省略。 |
| `imageConfig.imageSize` | 分辨率档位，例如 `1K`、`2K`、`4K`；以当前模型和服务端支持范围为准。 |

### 原生响应

图片通常位于 `candidates[0].content.parts` 的 `inlineData` 节点：

```json
{
  "candidates": [
    {
      "content": {
        "parts": [
          {
            "inlineData": {
              "mimeType": "image/png",
              "data": "<BASE64>"
            }
          }
        ]
      }
    }
  ]
}
```

## Gemini 原生图生图

### Base64 输入

在 `parts` 中同时传文字和 `inlineData`。输入图片使用原生 Gemini 的 camelCase 字段：

```json
{
  "contents": [{
    "role": "user",
    "parts": [
      { "text": "改成日系水彩风，保留主体和构图" },
      {
        "inlineData": {
          "mimeType": "image/png",
          "data": "<BASE64>"
        }
      }
    ]
  }],
  "generationConfig": {
    "responseModalities": ["IMAGE"],
    "imageConfig": { "imageSize": "2K" }
  }
}
```

### URL 输入

如果服务端支持远程图片输入，可以使用 `fileData`：

```json
{
  "fileData": {
    "mimeType": "image/png",
    "fileUri": "https://example.com/input.png"
  }
}
```

省略 `imageConfig.aspectRatio` 时，服务端可以根据参考图决定比例；需要固定比例时再传 `aspectRatio`。

## 常见问题

### OpenAI 和 Gemini 请求能混用吗？

不能直接混用字段。OpenAI 兼容入口使用 `model`、`prompt`、`size` 和 `response_format`；Gemini 原生入口使用 `contents`、`generationConfig.responseModalities` 和 `generationConfig.imageConfig`。模型可以相同，但请求体要按入口书写。

### `nano-banana-2` 和 `nano-banana-pro` 怎么选？

先使用 `nano-banana-2` 验证请求格式和业务流程；需要使用 Pro 模型时把模型名替换为 `nano-banana-pro`，其他字段保持不变。具体速度、额度和可用尺寸以服务端当前配置为准。

### 为什么看不到图片？

先检查响应是否包含 `candidates[].content.parts[].inlineData.data`，并根据 `mimeType` 拼接 `data:{mimeType};base64,{data}`。如果使用 OpenAI 兼容格式，则读取 `data[0].url` 或 `data[0].b64_json`。

长段中文仍可能出现错字、漏字或顺序错误。图片适合做构图和视觉草稿；需要准确排版的标题、条款或正文，建议生成后在设计软件中添加。
