## 模型

调用方式完全一致，只换模型名：

| 模型名 | 取向 |
| --- | --- |
| `gemini-3-pro-image-preview` | 画质优先 |
| `gemini-3.1-flash-image-preview` | 速度优先；额外支持 `8:1` / `4:1` / `1:4` / `1:8` 超宽长条 |
| `gemini-3-pro-image-preview-c` | Pro 企业模型；支持原生 4K、并发，100% 成功率 |
| `gemini-3.1-flash-image-preview-c` | Flash 企业模型；支持原生 4K、并发，100% 成功率 |

企业模型与普通模型使用相同的 Gemini 原生调用格式，只需替换 URL 中的模型名。

## 参数

为了兼容 Gemini 原生参数和当前接口，比例与分辨率建议同时填写在 `generationConfig.imageConfig` 和 `generationConfig.responseFormat.image`，两处值保持一致：

| 参数 | 说明 |
| --- | --- |
| `imageConfig.aspectRatio` | Gemini 原生比例参数，见下表；图生图省略时根据参考图自动决定 |
| `imageConfig.imageSize` | Gemini 原生分辨率参数：`1K` / `2K` / `4K`，K 必须大写 |
| `responseFormat.image` | 接口兼容参数；复制相同的 `aspectRatio` 和 `imageSize` |
| `responseModalities` | `["IMAGE"]` 返回 base64、`["TEXT"]` 返回 URL、`["IMAGE","TEXT"]` 两者都返回 |

> 请求 2K / 4K 时请同时传两组参数。只传 `responseFormat.image` 可能仍按默认 1K 生成，例如 `3:4` 只得到 896×1200。

> 自动比例不要传 `aspectRatio: "auto"`，正确写法是省略 `aspectRatio`。

## 支持的比例与像素

10 个通用比例，四个模型都支持：

| 比例 | 1K | 2K | 4K |
| --- | --- | --- | --- |
| `1:1` | 1024×1024 | 2048×2048 | 4096×4096 |
| `16:9` | 1376×768 | 2752×1536 | 5504×3072 |
| `9:16` | 768×1376 | 1536×2752 | 3072×5504 |
| `4:3` | 1200×896 | 2400×1792 | 4800×3584 |
| `3:4` | 896×1200 | 1792×2400 | 3584×4800 |
| `3:2` | 1264×848 | 2528×1696 | 5056×3392 |
| `2:3` | 848×1264 | 1696×2528 | 3392×5056 |
| `5:4` | 1152×928 | 2304×1856 | 4608×3712 |
| `4:5` | 928×1152 | 1856×2304 | 3712×4608 |
| `21:9` | 1584×672 | 3168×1344 | 6336×2688 |

超宽长条仅 Flash 系列 `gemini-3.1-flash-image-preview` 与 `gemini-3.1-flash-image-preview-c` 支持：`8:1` = 2928×352、`4:1` = 2064×512、`1:4` = 512×2064、`1:8` = 352×2928，2K / 4K 对应放大 2 / 4 倍。

> 模型适合生成建筑、色彩和构图，但长段中文仍可能出现错字、漏字或顺序错误。正文排版建议在生成图片后使用设计软件添加，不要把图片中的长文本直接作为最终文稿。

### 稳定请求 4K

下面以 `3:4` 为例。两组尺寸参数必须一致：

```json
{
  "generationConfig": {
    "responseModalities": ["IMAGE"],
    "imageConfig": {
      "aspectRatio": "3:4",
      "imageSize": "4K"
    },
    "responseFormat": {
      "image": {
        "aspectRatio": "3:4",
        "imageSize": "4K"
      }
    }
  }
}
```

`3:4` 的 4K 结果应为约 3584×4800；如果实际只有 896×1200，说明请求仍按 1K 处理。

图片位于 `candidates[0].content.parts[0].inline_data.data`。

### 文生图 → URL

把 `responseModalities` 改成 `["TEXT"]`，URL 位于 `candidates[0].content.parts[1].file_data.file_uri`。同时需要 base64 和 URL 时使用 `["IMAGE","TEXT"]`。

### 图生图（输入 base64）

在 `parts` 中于文本之外加入一个图片 part：

```bash
curl -X POST "https://api.klong.lat/v1beta/models/gemini-3-pro-image-preview:generateContent" \
  -H "x-goog-api-key: <API_KEY>" \
  -H "Content-Type: application/json" \
  -d '{
    "contents": [{
      "role": "user",
      "parts": [
        { "text": "改成日系水彩风，保留主体和构图" },
        {
          "inline_data": {
            "mime_type": "image/png",
            "data": "<BASE64>"
          }
        }
      ]
    }],
    "generationConfig": {
      "responseModalities": ["IMAGE"]
    }
  }'
```

### 图生图（输入 URL）

把上面的 `inline_data` 换成：

```json
{
  "file_data": {
    "mime_type": "image/png",
    "file_uri": "https://example.com/input.png"
  }
}
```

### 图生图自动跟随参考图比例，并固定 2K

两处都只传 `imageSize`，省略 `aspectRatio`：

```json
{
  "generationConfig": {
    "responseModalities": ["IMAGE"],
    "imageConfig": {
      "imageSize": "2K"
    },
    "responseFormat": {
      "image": { "imageSize": "2K" }
    }
  }
}
```

`aspectRatio` 和 `imageSize` 都省略时，参考图比例和输出档位由上游决定；文生图需要固定形状时，建议同时传比例和分辨率。
