This page covers two separate integration routes. `nano-banana2` and `nano-banana-pro` are relayed through NewAPI and use only the OpenAI Images API. `gemini-3.1-flash-image-preview` and `gemini-3-pro-image-preview` use the native Gemini protocol. These names are not interchangeable aliases; select the endpoint and request body by model.

## Basic information

| Item | Value |
| --- | --- |
| API root | `https://api.klong.lat` |
| OpenAI SDK Base URL | `https://api.klong.lat/v1` |
| OpenAI authentication | `Authorization: Bearer <API_KEY>` |
| Gemini authentication | Prefer `x-goog-api-key: <API_KEY>`; the other native forms listed below are also supported |
| Image storage | A returned image URL may not be permanent; copy the result to your own object storage promptly |

## Models

| Model | Protocol | Endpoint |
| --- | --- | --- |
| `nano-banana2` | OpenAI Images API (via NewAPI) | `POST /v1/images/generations` or `/v1/images/edits` |
| `nano-banana-pro` | OpenAI Images API (via NewAPI) | `POST /v1/images/generations` or `/v1/images/edits` |
| `gemini-3.1-flash-image-preview` | Native Gemini | `POST /v1beta/models/{model}:generateContent` |
| `gemini-3-pro-image-preview` | Native Gemini | `POST /v1beta/models/{model}:generateContent` |

The model ID determines the protocol as well as the capability. The `nano-*` models do not expose a native Gemini format, so do not place them in a Gemini URL. Do not send the two `gemini-*` models to the OpenAI Images API either.

## Choose a request format

| Need | Endpoint |
| --- | --- |
| Generate with `nano-banana2` or `nano-banana-pro` | `POST /v1/images/generations` |
| Edit with `nano-banana2` or `nano-banana-pro` | `POST /v1/images/edits` |
| Use `gemini-3.1-flash-image-preview` or `gemini-3-pro-image-preview` | `POST /v1beta/models/{model}:generateContent` |
| Stream through the native Gemini protocol | Change the method to `:streamGenerateContent`; keep the request body the same |

## OpenAI Images API

This section applies only to `nano-banana2` and `nano-banana-pro` as relayed through NewAPI. The current integration exposes only the OpenAI Images API; it does not provide a native Gemini format and does not use `/v1/chat/completions`.

### Images API text to image

```http
POST https://api.klong.lat/v1/images/generations
Authorization: Bearer <API_KEY>
Content-Type: application/json
```

```json
{
  "model": "nano-banana2",
  "prompt": "A red apple on a wooden table, soft studio light, minimal background",
  "size": "1024x1024",
  "response_format": "url"
}
```

The `nano-banana-pro` request is identical; change only `model`. When `response_format` is omitted, the service returns a URL by default. Pass `b64_json` explicitly for Base64.

`size` accepts a pixel size such as `1024x1024`, an aspect ratio such as `16:9`, or a resolution tier such as `2K`. A pixel size is mapped to the nearest supported aspect ratio and tier; the returned image is authoritative.

A typical response looks like this. Read the image from `data[].url`, or from `data[].b64_json` when Base64 output is selected:

```json
{
  "created": 1787600000,
  "data": [
    { "url": "<IMAGE_URL>" }
  ],
  "usage": {
    "input_tokens": 8,
    "output_tokens": 1124,
    "total_tokens": 1132
  }
}
```

### Images API image editing

```http
POST https://api.klong.lat/v1/images/edits
Authorization: Bearer <API_KEY>
Content-Type: multipart/form-data
```

```bash
curl -X POST "https://api.klong.lat/v1/images/edits" \
  -H "Authorization: Bearer <API_KEY>" \
  -F "model=nano-banana2" \
  -F "prompt=Restyle this image as Japanese watercolor while preserving the subject and composition" \
  -F "response_format=url" \
  -F "image=@input.png"
```

In addition to OpenAI-style `multipart/form-data`, a JSON request may contain image URLs or Data URLs. Use `image`; the service also accepts `image_url`, `images`, and `reference_images`. Pass a string for one image or an array for multiple images:

```http
POST https://api.klong.lat/v1/images/edits
Authorization: Bearer <API_KEY>
Content-Type: application/json
```

```json
{
  "model": "nano-banana-pro",
  "prompt": "Replace the background with a night scene",
  "image": [
    "https://your-domain.example/a.png",
    "https://your-domain.example/b.png"
  ],
  "size": "2K"
}
```

## Native Gemini format

This section applies only to `gemini-3.1-flash-image-preview` and `gemini-3-pro-image-preview`, using fields from the native Gemini protocol.

### URL and headers

```http
POST https://api.klong.lat/v1beta/models/{model}:generateContent
x-goog-api-key: <API_KEY>
Content-Type: application/json
```

Replace `{model}` with `gemini-3.1-flash-image-preview` or `gemini-3-pro-image-preview`. Native Gemini requests use `generationConfig.imageConfig` for ratio and resolution.

The native Gemini protocol supports three authentication forms. Choose one; there is no need to send more than one in a request:

- `x-goog-api-key: <API_KEY>` (commonly used by Google SDKs)
- `Authorization: Bearer <API_KEY>`
- Append `?key=<API_KEY>` to the URL

The `x-goog-api-key` header shown above is recommended. This page consistently uses `/v1beta/models/...`; `/v1/models/...` may also be used when enabled by the current service.

### Native text-to-image request

```json
{
  "contents": [
    {
      "role": "user",
      "parts": [
        { "text": "A red apple on a wooden table, soft studio light, minimal background" }
      ]
    }
  ],
  "generationConfig": {
    "responseModalities": ["IMAGE"],
    "imageConfig": {
      "aspectRatio": "1:1",
      "imageSize": "1K"
    }
  }
}
```

OpenAI `size` and `response_format` fields do not belong in a native Gemini request. Use `generationConfig.imageConfig` for both ratio and resolution:

| Field | Description |
| --- | --- |
| `responseModalities` | Use `['IMAGE']` to request an image. |
| `imageConfig.aspectRatio` | An image ratio such as `1:1`, `16:9`, or `3:4`. Omit it when the ratio should be automatic. |
| `imageConfig.imageSize` | A resolution tier such as `1K`, `2K`, or `4K`, subject to the current model and service configuration. |

Some upstream deployments also expose ultra-wide ratios such as `8:1`, `4:1`, `1:4`, and `1:8`. They are not enabled for every model or deployment; use them only when the service explicitly supports them and the request succeeds. On `400`, fall back to one of the common ratios above.

Common reference implementations use the following 1K dimensions. If the service scales the same ratio, 2K and 4K are often approximately 2x and 4x these values, but the actual response dimensions are authoritative:

| Ratio | Reference 1K size |
| --- | --- |
| `8:1` | 2928×352 |
| `4:1` | 2064×512 |
| `1:4` | 512×2064 |
| `1:8` | 352×2928 |

`imageSize` must use uppercase `1K`, `2K`, or `4K`. Omit both `aspectRatio` and `imageSize` to let the upstream choose. Do not send `aspectRatio: "auto"`; omit the field when the ratio should be automatic.

### Response format

`responseModalities` selects what the model generates; it does not decide whether an image is encoded as Base64 or returned as a URL in the JSON response. Continue to use `['IMAGE']` for image generation. Do not switch to `['TEXT']` merely to request a URL.

Current tests against `https://api.klong.lat` return an image URL in `candidates[].content.parts[]` instead of always returning `inlineData`. Iterate over every `part` and read it by field name rather than assuming a fixed array index:

| Response field | Use |
| --- | --- |
| `file_data.file_uri` or `fileData.fileUri` | Direct image URL and the primary form returned by the current service. |
| `text` | May contain a Markdown link to the same image, such as `![Generated Image](<IMAGE_URL>)`. |
| `inline_data.data` or `inlineData.data` | A Base64 image that some upstreams may return; decode it with the corresponding MIME type. |

Prefer the URL from `file_data` / `fileData`, then extract a URL from `text`. If `inline_data` / `inlineData` is present, handle it as Base64. The absence of `inlineData` alone does not mean generation failed.

> Keep ratio and resolution under `generationConfig.imageConfig`. Do not add OpenAI `response_format` or `responseFormat` fields to a Gemini request.

### Aspect ratio and resolution quick reference

The following are common target pixels for Gemini image models. The actual dimensions remain subject to the selected model and service configuration:

| Ratio | 1K | 2K | 4K |
| --- | --- | --- | --- |
| `1:1` | 1024×1024 | 2048×2048 | 4096×4096 |
| `16:9` | 1376×768 | 2752×1536 | 5504×3072 |
| `9:16` | 768×1376 | 1536×2752 | 3072×5504 |
| `4:3` | 1200×896 | 2400×1792 | 4800×3584 |
| `3:4` | 896×1200 | 1792×2400 | 3584×4800 |
| `3:2` | 1264×848 | 2528×1696 | 5056×3392 |
| `2:3` | 848×1264 | 1696×2528 | 3392×5056 |
| `5:4` | 1152×928 | 2304×1856 | 4608×3712 |
| `4:5` | 928×1152 | 1856×2304 | 3712×4608 |
| `21:9` | 1584×672 | 3168×1344 | 6336×2688 |

Current service test: `gemini-3.1-flash-image-preview` with `aspectRatio: "1:1"` and `imageSize: "4K"` returned an actual `4096×4096` image.

### Current service response

The current service returns an image URL. A response may contain both `text` and `file_data`:

```json
{
  "candidates": [
    {
      "content": {
        "parts": [
          {
            "text": "![Generated Image](<IMAGE_URL>)"
          },
          {
            "file_data": {
              "mime_type": "image/jpeg",
              "file_uri": "<IMAGE_URL>"
            }
          }
        ]
      }
    }
  ]
}
```

Some clients expose the camelCase form `fileData.fileUri`. Also retain support for `inlineData` when another upstream returns a Base64 image.

## Native Gemini image editing

### Base64 input

Send text and `inlineData` in the same `parts` array. The examples consistently use Gemini REST camelCase fields; the service also accepts snake_case forms such as `inline_data` and `mime_type`:

```json
{
  "contents": [{
    "role": "user",
    "parts": [
      { "text": "Restyle this as Japanese watercolor while preserving the subject and composition" },
      {
        "inlineData": {
          "mimeType": "image/png",
          "data": "<BASE64>"
        }
      }
    ]
  }],
  "generationConfig": {
    "responseModalities": ["IMAGE"],
    "imageConfig": { "imageSize": "2K" }
  }
}
```

### URL input

If the service allows remote image input, use `fileData`:

```json
{
  "contents": [{
    "role": "user",
    "parts": [
      { "text": "Restyle this as Japanese watercolor while preserving the subject and composition" },
      {
        "fileData": {
          "mimeType": "image/png",
          "fileUri": "https://example.com/input.png"
        }
      }
    ]
  }],
  "generationConfig": {
    "responseModalities": ["IMAGE"],
    "imageConfig": { "imageSize": "2K" }
  }
}
```

`inlineData` and `fileData` are both image parts and may be mixed in the order used in `contents[].parts[]` when the service supports it. A remote URL must be reachable by the service. The commonly cited limit of 14 reference images is not a fixed promise of this endpoint; use the limit configured for the current model and service, and treat the actual error response as authoritative.

Omit `imageConfig.aspectRatio` to let the service follow the reference image ratio; pass it when a fixed ratio is needed.

## Errors and operational guidance

| HTTP status | Common cause | Suggested action |
| --- | --- | --- |
| `400` | Invalid request fields or content rejected by a safety policy | Check the protocol, model ID, parameters, and prompt |
| `401` | Missing or invalid API key | Check authentication and do not mix multiple auth forms |
| `402` | Insufficient account credit | Add credit, then retry |
| `429` | Too many requests or rate limiting | Reduce concurrency and retry later |
| `503` / `504` | Upstream busy or processing timeout | Retry later and retain the response ID for troubleshooting |

Image generation takes longer than text requests, and 4K output takes longer still. Set the client timeout to at least five minutes. Copy URL results to your own storage promptly so an expiring source URL does not become a problem.

## Common questions

### Can I mix OpenAI and Gemini fields?

No. The OpenAI Images API uses `model`, `prompt`, `size`, and `response_format`, and accepts only `nano-banana2` or `nano-banana-pro` from this page. The native Gemini endpoint uses `contents`, `generationConfig.responseModalities`, and `generationConfig.imageConfig`, and accepts only the two `gemini-*` models. Both the model ID and request fields must match the endpoint.

### Which model should I choose?

Start with `nano-banana2` to verify the request and product flow. To use Pro, change the model ID to `nano-banana-pro`; keep the other Images API fields unchanged. Actual speed, quota, and available sizes depend on the current service configuration.

### Where is the image in the response?

For native Gemini, iterate over `candidates[].content.parts[]`: prefer `file_data.file_uri` / `fileData.fileUri`, then extract a Markdown image URL from `text`; if `inline_data.data` / `inlineData.data` is returned, decode the Base64 value. For the OpenAI Images API, read `data[0].url` or `data[0].b64_json`.

Long text rendered inside an image can still contain missing, incorrect, or reordered characters. Use generated images for visual composition; add exact headings, clauses, or body copy in a design tool afterward.
