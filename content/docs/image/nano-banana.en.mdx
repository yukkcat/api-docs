Nano Banana supports two request formats: the OpenAI-compatible Images API and native Gemini `generateContent`. Both formats can generate images. For edits, use `/v1/images/edits` with the OpenAI-compatible format, or attach an image in `contents.parts` with the native Gemini format.

## Models

| Model | Description |
| --- | --- |
| `nano-banan2` | Nano Banana 2; supports the OpenAI Images API and native Gemini format. |
| `nano-banana-pro` | Nano Banana Pro; supports the OpenAI Images API and native Gemini format. |
| `gemini-3.1-flash-image-preview` | Compatibility model; use the native Gemini format on this page, with capabilities determined by the service configuration. |
| `gemini-3-pro-image-preview` | Compatibility model; use the native Gemini format on this page, with capabilities determined by the service configuration. |

Use the same model ID in the OpenAI request body and in the native Gemini model URL. All listed Gemini models use the same native parameters.

## Choose a request format

| Need | Endpoint |
| --- | --- |
| An OpenAI SDK or Images API client | `POST /v1/images/generations` |
| Image editing with OpenAI-compatible fields | `POST /v1/images/edits` |
| Native Gemini fields | `POST /v1beta/models/{model}:generateContent` |
| Native Gemini streaming | Change the method to `:streamGenerateContent`; keep the request body the same |

## OpenAI-compatible format

### Text to image

```http
POST https://api.klong.lat/v1/images/generations
Authorization: Bearer <API_KEY>
Content-Type: application/json
```

```json
{
  "model": "nano-banan2",
  "prompt": "A red apple on a wooden table, soft studio light, minimal background",
  "size": "1024x1024",
  "response_format": "url"
}
```

The `nano-banana-pro` request is identical; change only `model`. When `response_format` is omitted, the service returns a URL by default. Pass `b64_json` explicitly for Base64. Use a `size` supported by the current service configuration.

### Image editing

```http
POST https://api.klong.lat/v1/images/edits
Authorization: Bearer <API_KEY>
Content-Type: multipart/form-data
```

```bash
curl -X POST "https://api.klong.lat/v1/images/edits" \
  -H "Authorization: Bearer <API_KEY>" \
  -F "model=nano-banan2" \
  -F "prompt=Restyle this image as Japanese watercolor while preserving the subject and composition" \
  -F "response_format=url" \
  -F "image=@input.png"
```

The input can also be supplied with `image_url` or `image_b64`, depending on the service endpoint.

## Native Gemini format

### URL and headers

```http
POST https://api.klong.lat/v1beta/models/{model}:generateContent
x-goog-api-key: <API_KEY>
Content-Type: application/json
```

Replace `{model}` with `nano-banan2` or `nano-banana-pro`. Native Gemini requests use `generationConfig.imageConfig` for ratio and resolution.

If enabled by the current service, `Authorization: Bearer <API_KEY>` may also be accepted. Send only one authentication header per request; follow the service configuration.

### Native text-to-image request

```json
{
  "contents": [
    {
      "role": "user",
      "parts": [
        { "text": "A red apple on a wooden table, soft studio light, minimal background" }
      ]
    }
  ],
  "generationConfig": {
    "responseModalities": ["IMAGE"],
    "imageConfig": {
      "aspectRatio": "1:1",
      "imageSize": "1K"
    }
  }
}
```

OpenAI `size` and `response_format` fields do not belong in a native Gemini request. Use `generationConfig.imageConfig` for both ratio and resolution:

Some reference documents use `generationConfig.responseFormat.image`; that is a different service-version convention. This service currently handles native requests through `generationConfig.imageConfig`. Do not put both field sets in one request; the deployed service is authoritative.

| Field | Description |
| --- | --- |
| `responseModalities` | Use `['IMAGE']` to request an image. |
| `imageConfig.aspectRatio` | An image ratio such as `1:1`, `16:9`, or `3:4`. Omit it when the ratio should be automatic. |
| `imageConfig.imageSize` | A resolution tier such as `1K`, `2K`, or `4K`, subject to the current model and service configuration. |

Some upstream deployments also expose ultra-wide ratios such as `8:1`, `4:1`, `1:4`, and `1:8`. They are not enabled for every model or deployment; use them only when the service explicitly supports them and the request succeeds. On `400`, fall back to one of the common ratios above.

Common reference implementations use the following 1K dimensions. If the service scales the same ratio, 2K and 4K are often approximately 2x and 4x these values, but the actual response dimensions are authoritative:

| Ratio | Reference 1K size |
| --- | --- |
| `8:1` | 2928×352 |
| `4:1` | 2064×512 |
| `1:4` | 512×2064 |
| `1:8` | 352×2928 |

`imageSize` must use uppercase `1K`, `2K`, or `4K`. Omit both `aspectRatio` and `imageSize` to let the upstream choose. Do not send `aspectRatio: "auto"`; omit the field when the ratio should be automatic.

### Native response modes

`responseModalities` specifies which content types the response may contain:

| Value | Common result | Notes |
| --- | --- | --- |
| `['IMAGE']` | `inlineData` (Base64) | Recommended for native image responses on this page. |
| `['TEXT']` | `fileData.fileUri` or text | Only available when URL/text conversion is enabled by the service; do not assume every deployment supports it. |
| `['IMAGE', 'TEXT']` | Image plus URL/text | Mixed output also depends on the service configuration. |

Read `candidates[].content.parts[]` by field instead of assuming a fixed array index. A response may contain text before the image. The common fields are:

| Response field | Use |
| --- | --- |
| `inlineData.mimeType` + `inlineData.data` | Build `data:{mimeType};base64,{data}` to display or save the image. |
| `fileData.fileUri` | Read a service-generated image URL, when URL output is enabled. |
| `text` | Model-generated text; it does not necessarily contain an image. |

> Unless the service explicitly enables `TEXT` or mixed output, use `['IMAGE']` and treat the presence of `inlineData` as the success signal. Native requests use `imageConfig` only; do not add OpenAI `response_format` or `responseFormat` fields.

### Aspect ratio and resolution quick reference

The following are common target pixels for Gemini image models. The actual dimensions remain subject to the selected model and service configuration:

| Ratio | 1K | 2K | 4K |
| --- | --- | --- | --- |
| `1:1` | 1024×1024 | 2048×2048 | 4096×4096 |
| `16:9` | 1376×768 | 2752×1536 | 5504×3072 |
| `9:16` | 768×1376 | 1536×2752 | 3072×5504 |
| `4:3` | 1200×896 | 2400×1792 | 4800×3584 |
| `3:4` | 896×1200 | 1792×2400 | 3584×4800 |
| `3:2` | 1264×848 | 2528×1696 | 5056×3392 |
| `2:3` | 848×1264 | 1696×2528 | 3392×5056 |
| `5:4` | 1152×928 | 2304×1856 | 4608×3712 |
| `4:5` | 928×1152 | 1856×2304 | 3712×4608 |
| `21:9` | 1584×672 | 3168×1344 | 6336×2688 |

### Native response

The image is normally returned in the `inlineData` node under `candidates[0].content.parts`:

```json
{
  "candidates": [
    {
      "content": {
        "parts": [
          {
            "inlineData": {
              "mimeType": "image/png",
              "data": "<BASE64>"
            }
          }
        ]
      }
    }
  ]
}
```

## Native Gemini image editing

### Base64 input

Send text and `inlineData` in the same `parts` array. Native Gemini uses camelCase fields:

```json
{
  "contents": [{
    "role": "user",
    "parts": [
      { "text": "Restyle this as Japanese watercolor while preserving the subject and composition" },
      {
        "inlineData": {
          "mimeType": "image/png",
          "data": "<BASE64>"
        }
      }
    ]
  }],
  "generationConfig": {
    "responseModalities": ["IMAGE"],
    "imageConfig": { "imageSize": "2K" }
  }
}
```

### URL input

If the service allows remote image input, use `fileData`:

```json
{
  "contents": [{
    "role": "user",
    "parts": [
      { "text": "Restyle this as Japanese watercolor while preserving the subject and composition" },
      {
        "fileData": {
          "mimeType": "image/png",
          "fileUri": "https://example.com/input.png"
        }
      }
    ]
  }],
  "generationConfig": {
    "responseModalities": ["IMAGE"],
    "imageConfig": { "imageSize": "2K" }
  }
}
```

`inlineData` and `fileData` are both image parts and may be mixed in the order used in `contents[].parts[]` when the service supports it. A remote URL must be reachable by the service. The commonly cited limit of 14 reference images is not a fixed promise of this endpoint; use the limit configured for the current model and service, and treat the actual error response as authoritative.

Omit `imageConfig.aspectRatio` to let the service follow the reference image ratio; pass it when a fixed ratio is needed.

## Common questions

### Can I mix OpenAI and Gemini fields?

No. The OpenAI-compatible endpoint uses `model`, `prompt`, `size`, and `response_format`. The native Gemini endpoint uses `contents`, `generationConfig.responseModalities`, and `generationConfig.imageConfig`. The model can be the same, but the request body must match the endpoint.

### Which model should I choose?

Start with `nano-banan2` to verify the request and product flow. To use Pro, change the model ID to `nano-banana-pro`; keep the other fields unchanged. Actual speed, quota, and available sizes depend on the current service configuration.

### Where is the image in the response?

For native Gemini, check `candidates[].content.parts[].inlineData.data` and use its `mimeType` to build a data URL. For the OpenAI-compatible endpoint, read `data[0].url` or `data[0].b64_json`.

Long text rendered inside an image can still contain missing, incorrect, or reordered characters. Use generated images for visual composition; add exact headings, clauses, or body copy in a design tool afterward.
