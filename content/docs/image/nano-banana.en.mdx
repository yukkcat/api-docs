`nano-banana2` and `nano-banana-pro` use the same OpenAI Images request and response structure as the [GPT Image series](/en/docs/image/gpt-image-2). Keep model names intact. Available dimensions, image counts, and extensions depend on the selected model and channel.

The Nano models on this page use OpenAI Images. For requests using `contents` and `generationConfig`, use the Gemini image models listed in the [Gemini protocol](/en/docs/image/gemini) guide; do not substitute a Nano identifier into a Gemini path. Model availability depends on your key's group.

## Endpoints and authentication

| Item | Value |
| --- | --- |
| API root | `https://api.klong.lat` |
| OpenAI SDK Base URL | `https://api.klong.lat/v1` |
| Authentication | `Authorization: Bearer <API_KEY>` |
| Image generation | `POST /v1/images/generations` |
| Image editing | `POST /v1/images/edits` |
| Models | `nano-banana2`, `nano-banana-pro` |

## Generate an image

For an initial integration, specify pixel size, delivery, and file encoding explicitly, and use `n: 1`. To use Pro, change `model` to `nano-banana-pro`.

<Tabs items={['cURL', 'Python']}>
<Tab>

```bash
curl https://api.klong.lat/v1/images/generations \
  -H "Authorization: Bearer <API_KEY>" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "nano-banana2",
    "prompt": "A red apple on a wooden table, soft studio light, minimal background",
    "size": "1024x1024",
    "n": 1,
    "response_format": "url",
    "output_format": "webp"
  }'
```

</Tab>
<Tab>

Install `openai`, then run:

```python
from openai import OpenAI

client = OpenAI(
    api_key="<API_KEY>",
    base_url="https://api.klong.lat/v1",
)
result = client.images.generate(
    model="nano-banana2",
    prompt="A red apple on a wooden table, soft studio light, minimal background",
    response_format="url",
    size="1024x1024",
    n=1,
    extra_body={
        "output_format": "webp",
    },
)
print(result.data[0].url)
```

Use `extra_body` for service extensions that the SDK does not expose as named parameters.

</Tab>
</Tabs>

## Edit an image

Supply a prompt and reference image. JSON accepts URLs or Data URLs; multipart accepts local files. Dimension and delivery fields are the same as for generation.

<Tabs items={['JSON', 'multipart']}>
<Tab>

```bash
curl https://api.klong.lat/v1/images/edits \
  -H "Authorization: Bearer <API_KEY>" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "nano-banana-pro",
    "prompt": "Restyle as Japanese watercolor, preserving the subject and composition",
    "image": ["https://example.com/input.png"],
    "size": "1024x1024",
    "n": 1,
    "response_format": "url",
    "output_format": "png"
  }'
```

Replace the example URL with an image the service can access, or use `data:image/png;base64,<PNG_BASE64>`. Reference fields include `image`, `images`, `image_url`, and `reference_images`. Pass a string for one image or an array for several.

</Tab>
<Tab>

```bash
curl https://api.klong.lat/v1/images/edits \
  -H "Authorization: Bearer <API_KEY>" \
  -F "model=nano-banana2" \
  -F "prompt=Restyle as Japanese watercolor, preserving the subject and composition" \
  -F "image=@input.png" \
  -F "size=1024x1024" \
  -F "n=1" \
  -F "response_format=b64_json" \
  -F "output_format=png"
```

Repeat `image[]` for multiple files. Let cURL set the `Content-Type` with its multipart boundary.

</Tab>
</Tabs>

## Dimensions, delivery, and encoding

| Parameter | Controls | Examples |
| --- | --- | --- |
| `size` | Target pixels | `"2048x2048"` |
| `aspect_ratio` | Image ratio | `"16:9"` |
| `image_size` | Resolution tier | `"1K"`, `"2K"`, `"4K"` |
| `response_format` | URL or Base64 delivery | `"url"`, `"b64_json"` |
| `output_format` | Actual image file encoding | `"png"`, `"jpeg"`, `"webp"` |

An explicit pixel `size` takes precedence over an accompanying ratio and tier. Alternatively, omit `size` and set `aspect_ratio: "16:9"` with `image_size: "2K"`. The Nano2 output tested on September 24, 2026 was `2752x1536`, not a fixed `2048x1152`. The platform also accepts a ratio or tier alone, subject to upstream capabilities; this test run did not exhaust those combinations or 4K. Exact output pixels depend on the channel's size processing mode; a requested `size` alone does not establish the actual output dimensions.

`output_format: "webp"` works with either URL or Base64 delivery. Omitting it preserves the image encoding after processing. JPEG conversion places transparent areas on a white background. See [OpenAI image parameters](/en/docs/image/openai-parameters) for precedence, compatibility aliases, and dimension limits.

## Read the result

Non-streaming images are in the `data` array. Delivery precedence is **the group's forced policy > the request's `response_format` > the group's default policy**. Groups can default to URL or Base64, or force either format. An explicit selector takes effect only when not overridden by a forced policy. The following examples assume no forced override.

<Tabs items={['URL', 'Base64']}>
<Tab>

With `response_format: "url"`:

```json
{
  "created": 1787600000,
  "data": [{"url": "https://example.com/images/result.webp"}]
}
```

Read `data[].url` and copy images you need to retain to your own storage.

</Tab>
<Tab>

With `response_format: "b64_json"` and `output_format: "webp"`:

```json
{
  "created": 1787600000,
  "data": [{"b64_json": "<WEBP_BASE64>"}]
}
```

`b64_json` has no Data URL prefix. Change `response_format` to `b64_json` in the Python SDK example above, then save the result:

```python
import base64
from pathlib import Path

for index, item in enumerate(result.data):
    Path(f"result-{index}.webp").write_bytes(base64.b64decode(item.b64_json))
```

</Tab>
</Tabs>

These responses omit usage and other fields. Images responses differ from Chat Markdown images and Gemini `candidates[].content.parts[]`. Where the channel supports Images streaming, completion events for `stream: true` use `url` or `b64_json` according to the effective delivery policy. URL events are a platform extension; see the format in the [GPT Image series](/en/docs/image/gpt-image-2) guide. This does not mean Images SSE was verified for every Nano model in this test run.

## Verified scope and limitations

Live testing on September 24, 2026 covered Nano2/Pro generation and editing, URL/Base64, and selected PNG/JPEG/WebP combinations. Nano2 standard Chat editing and Chat SSE were also tested; SSE initially returned 400 and succeeded on retry. This does not establish error-free behavior for every model and protocol combination.

- Prefer `n: 1`. Reference-image count and output-image count are different; verify multiple-image support for the channel.
- The API does not currently support `mask` or `output_compression`. `background` does not provide transparent-background control.
- NewAPI Chat rejects string image selectors such as `response_format: "url"` or `"b64_json"`. Use the group's delivery default, or use the Images endpoints on this page for per-request delivery selection.
- Nano Responses was not verified end to end in this run. Merely replacing the model in a GPT Responses example does not establish support. See [Chat and Responses images](/en/docs/image/openai-chat-responses) for verified Chat requests and responses.
