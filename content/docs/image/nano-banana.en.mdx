Nano Banana supports two request formats: the OpenAI-compatible Images API and native Gemini `generateContent`. Both formats can generate images. For edits, use `/v1/images/edits` with the OpenAI-compatible format, or attach an image in `contents.parts` with the native Gemini format.

## Models

| Model | Description |
| --- | --- |
| `nano-banana-2` | The newer Nano Banana model; supports the OpenAI Images API and native Gemini format. |
| `nano-banana-pro` | Nano Banana Pro; supports the OpenAI Images API and native Gemini format. |
| `gemini-3.1-flash-image-preview` | Compatibility model; use the native Gemini format on this page, with capabilities determined by the service configuration. |
| `gemini-3-pro-image-preview` | Compatibility model; use the native Gemini format on this page, with capabilities determined by the service configuration. |

Use the same model ID in the OpenAI request body and in the native Gemini model URL. All listed Gemini models use the same native parameters.

## Choose a request format

| Need | Endpoint |
| --- | --- |
| An OpenAI SDK or Images API client | `POST /v1/images/generations` |
| Image editing with OpenAI-compatible fields | `POST /v1/images/edits` |
| Native Gemini fields | `POST /v1beta/models/{model}:generateContent` |
| Native Gemini streaming | Change the method to `:streamGenerateContent`; keep the request body the same |

## OpenAI-compatible format

### Text to image

```http
POST https://api.klong.lat/v1/images/generations
Authorization: Bearer <API_KEY>
Content-Type: application/json
```

```json
{
  "model": "nano-banana-2",
  "prompt": "A red apple on a wooden table, soft studio light, minimal background",
  "size": "1024x1024",
  "response_format": "url"
}
```

The `nano-banana-pro` request is identical; change only `model`. When `response_format` is omitted, the service returns a URL by default. Pass `b64_json` explicitly for Base64. Use a `size` supported by the current service configuration.

### Image editing

```http
POST https://api.klong.lat/v1/images/edits
Authorization: Bearer <API_KEY>
Content-Type: multipart/form-data
```

```bash
curl -X POST "https://api.klong.lat/v1/images/edits" \
  -H "Authorization: Bearer <API_KEY>" \
  -F "model=nano-banana-2" \
  -F "prompt=Restyle this image as Japanese watercolor while preserving the subject and composition" \
  -F "response_format=url" \
  -F "image=@input.png"
```

The input can also be supplied with `image_url` or `image_b64`, depending on the service endpoint.

## Native Gemini format

### URL and headers

```http
POST https://api.klong.lat/v1beta/models/{model}:generateContent
x-goog-api-key: <API_KEY>
Content-Type: application/json
```

Replace `{model}` with `nano-banana-2` or `nano-banana-pro`. Native Gemini requests use `generationConfig.imageConfig` for ratio and resolution.

### Native text-to-image request

```json
{
  "contents": [
    {
      "role": "user",
      "parts": [
        { "text": "A red apple on a wooden table, soft studio light, minimal background" }
      ]
    }
  ],
  "generationConfig": {
    "responseModalities": ["IMAGE"],
    "imageConfig": {
      "aspectRatio": "1:1",
      "imageSize": "1K"
    }
  }
}
```

OpenAI `size` and `response_format` fields do not belong in a native Gemini request. Use `generationConfig.imageConfig` for both ratio and resolution:

| Field | Description |
| --- | --- |
| `responseModalities` | Use `['IMAGE']` to request an image. |
| `imageConfig.aspectRatio` | An image ratio such as `1:1`, `16:9`, or `3:4`. Omit it when the ratio should be automatic. |
| `imageConfig.imageSize` | A resolution tier such as `1K`, `2K`, or `4K`, subject to the current model and service configuration. |

### Native response

The image is normally returned in the `inlineData` node under `candidates[0].content.parts`:

```json
{
  "candidates": [
    {
      "content": {
        "parts": [
          {
            "inlineData": {
              "mimeType": "image/png",
              "data": "<BASE64>"
            }
          }
        ]
      }
    }
  ]
}
```

## Native Gemini image editing

### Base64 input

Send text and `inlineData` in the same `parts` array. Native Gemini uses camelCase fields:

```json
{
  "contents": [{
    "role": "user",
    "parts": [
      { "text": "Restyle this as Japanese watercolor while preserving the subject and composition" },
      {
        "inlineData": {
          "mimeType": "image/png",
          "data": "<BASE64>"
        }
      }
    ]
  }],
  "generationConfig": {
    "responseModalities": ["IMAGE"],
    "imageConfig": { "imageSize": "2K" }
  }
}
```

### URL input

If the service allows remote image input, use `fileData`:

```json
{
  "fileData": {
    "mimeType": "image/png",
    "fileUri": "https://example.com/input.png"
  }
}
```

Omit `imageConfig.aspectRatio` to let the service follow the reference image ratio; pass it when a fixed ratio is needed.

## Common questions

### Can I mix OpenAI and Gemini fields?

No. The OpenAI-compatible endpoint uses `model`, `prompt`, `size`, and `response_format`. The native Gemini endpoint uses `contents`, `generationConfig.responseModalities`, and `generationConfig.imageConfig`. The model can be the same, but the request body must match the endpoint.

### Which model should I choose?

Start with `nano-banana-2` to verify the request and product flow. To use Pro, change the model ID to `nano-banana-pro`; keep the other fields unchanged. Actual speed, quota, and available sizes depend on the current service configuration.

### Where is the image in the response?

For native Gemini, check `candidates[].content.parts[].inlineData.data` and use its `mimeType` to build a data URL. For the OpenAI-compatible endpoint, read `data[0].url` or `data[0].b64_json`.

Long text rendered inside an image can still contain missing, incorrect, or reordered characters. Use generated images for visual composition; add exact headings, clauses, or body copy in a design tool afterward.
