The GPT Image series uses OpenAI-compatible endpoints. Examples use the tested `gpt-image-2-high` and `gpt-image-2-vip` identifiers. Use a model available to your key's group and preserve its complete name; do not split or replace suffixes. Existing names such as `gpt-image-2`, `gpt-image-2.5`, and `-exact` or `-1k` variants are not renamed by these examples. See [Models](/en/docs/models/overview) for groups and channel differences.

The [Nano Banana series](/en/docs/image/nano-banana) shares the Images request and response structure; the [Gemini protocol](/en/docs/image/gemini) uses a different body. Dimensions, delivery, and file encodings are described in [OpenAI image parameters](/en/docs/image/openai-parameters). A shared format does not mean every model channel supports every extension.

## Endpoints and authentication

Use `https://api.klong.lat/v1` as the SDK `base_url`. The API root is `https://api.klong.lat`.

| POST path | Purpose | Image location |
| --- | --- | --- |
| `/v1/images/generations` | JSON text-to-image | `data[].url` or `data[].b64_json` |
| `/v1/images/edits` | JSON or multipart editing | `data[].url` or `data[].b64_json` |
| `/v1/chat/completions` | Messages for a GPT image model | Markdown images in `choices[].message.content` |
| `/v1/responses` | `input` with the `image_generation` tool | Image tool `result` in `output[]` |

All requests use `Authorization: Bearer <API_KEY>`. The following examples target the GPT image channel; full Chat and Responses formats are in [Chat and Responses images](/en/docs/image/openai-chat-responses).

## Generate an image

At minimum, supply `model` and `prompt`. For an initial integration, use `n: 1`, an explicit pixel size, and an explicit delivery format to verify that one image can be read correctly.

```bash
curl https://api.klong.lat/v1/images/generations \
  -H "Authorization: Bearer <API_KEY>" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "gpt-image-2-high",
    "prompt": "A misty mountain valley at dawn, cool blue palette, minimal illustration",
    "size": "1024x1024",
    "response_format": "url",
    "output_format": "webp",
    "n": 1
  }'
```

```python
from openai import OpenAI

client = OpenAI(
    api_key="<API_KEY>",

result = client.images.generate(

```

`n` defaults to `1`. Multiple-image behavior depends on the model and execution mode: in testing on September 24, 2026, a non-streaming `gpt-image-2-vip` Images request with `n: 2` returned only one image. `gpt-image-2-high` Images SSE returned two different images, generated sequentially. Prefer `n: 1` in production integrations; when requesting more, check the actual output count rather than treating HTTP 200 as proof that every image was delivered.

### Aspect ratio and resolution tier

When exact pixels are not required, replace `size` with:

```json
{
  "aspect_ratio": "16:9",
  "image_size": "2K"
}
```

An explicit pixel `size` takes precedence over these fields. A ratio and tier do not guarantee fixed pixels: the tested GPT `16:9 + 2K` output was `2560x1440`; `image_size: "2K"` alone produced `2048x2048`. Final dimensions also depend on channel processing.

One request using only `aspect_ratio: "16:9"` was translated to `1024x576` and rejected by the upstream minimum-pixel constraint. Success on an identical retry does not establish that the combination is reliable. For initial integrations, prefer tested explicit dimensions such as `1024x1024` or `1536x1024`. See [OpenAI image parameters](/en/docs/image/openai-parameters) for the complete rules.

## Edit an image

Provide `prompt` and at least one reference image. You can also set `aspect_ratio`, `image_size`, `size`, `response_format`, and `output_format`. Omitted dimensions are left to the upstream service; the reference image's exact pixels are not guaranteed.

### JSON: URL or Data URL

```bash
curl https://api.klong.lat/v1/images/edits \
  -H "Authorization: Bearer <API_KEY>" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "gpt-image-2-vip",
    "prompt": "Put a beret on the otter, preserving the original lighting",
    "reference_images": ["data:image/png;base64,<PNG_BASE64>"],
    "size": "1024x1024",
    "n": 1,
    "response_format": "b64_json",
    "output_format": "png"
  }'
```

Replace `<PNG_BASE64>` with real image data, or supply an HTTPS image URL accessible to the server in the `reference_images` array. The platform also accepts reference fields such as `image`, `image_url`, and `images`; use one form per request. Multiple-reference support and results depend on the channel; not every combination has been tested.

GPT `/generations` also enters the edit flow when references are supplied. New integrations should explicitly use `/edits`.

### multipart: local files

```bash
curl https://api.klong.lat/v1/images/edits \
  -H "Authorization: Bearer <API_KEY>" \
  -F "model=gpt-image-2-vip" \
  -F "image=@input.png" \
  -F "prompt=Change the blue circle to red, preserving the other elements" \
  -F "size=1024x1024" \
  -F "n=1" \
  -F "response_format=url" \
  -F "output_format=jpeg"
```

Use one `image` file field for a single reference. Repeat `image[]` for multiple references; upstream acceptance still depends on the channel. Let the client create the multipart boundary instead of manually setting `Content-Type`.

```python
with open("input.png", "rb") as reference:
    result = client.images.edit(
        model="gpt-image-2-vip",
        image=reference,
        prompt="Change the blue circle to red, preserving the other elements",
        size="1024x1024",
        n=1,
        response_format="url",
        extra_body={"output_format": "jpeg"},
    )
print(result.data[0].url)
```

## Read the result

Delivery precedence is **the group's forced policy > the request's `response_format` > the group's default policy**. A group can default to URL or Base64, or force either format. The following examples assume no forced override. Omitting the selector does not mean every group returns URLs.

### URL

With `response_format: "url"`, images are in `data[].url`. This response omits some fields:

```json
{
  "created": 1790120000,
  "data": [
    {
      "url": "https://api.klong.lat/images/example.webp",
      "revised_prompt": "A misty mountain valley at dawn, cool blue palette, minimal illustration"
    }
  ],
  "usage": {"estimated": true}
}
```

`usage` may also contain input, output, and total tokens; `estimated: true` identifies an estimated usage value. Use the URL from the actual response and copy images to your own storage when long-term retention is needed.

### Base64

Set `response_format: "b64_json"` to receive image items in this form:

```json
{
  "b64_json": "<WEBP_BASE64>",
  "revised_prompt": "A misty mountain valley at dawn, cool blue palette, minimal illustration"
}
```

`b64_json` encodes image bytes without a `data:` prefix. Specify `output_format` and save with the matching extension:

```python
import base64
from pathlib import Path

result = client.images.generate(
    model="gpt-image-2-high",
    prompt="A misty mountain valley at dawn, cool blue palette, minimal illustration",
    response_format="b64_json",
    size="1024x1024",
    n=1,
    extra_body={"output_format": "webp"},
)
Path("result.webp").write_bytes(base64.b64decode(result.data[0].b64_json))
```

## Images streaming

Add `"stream": true` to JSON, or `-F "stream=true"` to multipart. With cURL, use `-N` to disable output buffering.

```bash
curl -N https://api.klong.lat/v1/images/generations \
  -H "Authorization: Bearer <API_KEY>" \
  -H "Content-Type: application/json" \
  -d '{"model":"gpt-image-2-high","prompt":"Draw a tree","size":"1024x1024","n":1,"stream":true,"response_format":"url","output_format":"png"}'
```

```text
event: image_generation.completed
data: {"type":"image_generation.completed","url":"https://example.com/result.png","output_format":"png","size":"1024x1024"}
```

This shows selected event fields. Edits return `image_edit.completed`, including references submitted to `/generations`. Each completed image produces a completion event; `size` contains that image's actual pixels.

Images SSE follows the effective delivery policy: completion events contain `url` in URL mode or `b64_json` in Base64 mode. URL completion events are a platform compatibility extension; do not assume every official SDK can consume them directly. Streaming sends complete images, without intermediate frames or live progress percentages. Ignore SSE comments such as `: keep-alive`.

## Verified scope and limitations

Live testing on September 24, 2026 covered high generation, vip editing, URL/Base64, selected pixel sizes, PNG/JPEG/WebP, and Images SSE. This is not certification of every model and parameter combination.

- The API does not currently support `mask` or `output_compression`. `background` does not provide transparent-background control.
- `output_format` controls file encoding; JPEG, PNG, and WebP are separate from delivery format. The `jpg` alias for JPEG was tested.
- Chat and Responses have separate limitations. Do not copy Images parameters unchanged; in particular, NewAPI Chat rejects the string image-delivery `response_format`. See [Chat and Responses images](/en/docs/image/openai-chat-responses).

## Error handling

Check the HTTP status before reading `error.message`. An edit without a reference image, for example, returns:

```json
{
  "error": {
    "message": "image file or image_url is required",
    "type": "invalid_request_error",
    "param": "image",
    "code": "request_invalid"
  }
}
```

The SDK raises `APIStatusError` for unsuccessful HTTP responses:

```python
from openai import APIStatusError

try:
    result = client.images.generate(
        model="gpt-image-2-high", prompt="Draw a tree",
        size="1024x1024", n=1, response_format="url",
    )
except APIStatusError as exc:
    body = exc.response.json()
    error = body.get("error", {})
    print(exc.status_code, error.get("code"), error.get("message"))
```

`type`, `param`, and `code` can vary or be absent. Correct invalid parameters; handle rate limits and upstream failures according to the HTTP status and error code, avoiding unconditional regeneration. After an Images SSE connection starts, it can emit `event: error` with the same error object in `data.error`; treat it as a failed request.
